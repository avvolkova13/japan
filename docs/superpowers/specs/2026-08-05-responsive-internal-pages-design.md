# Responsive Internal Pages Design

## Цель

Проверить и аккуратно исправить адаптивное поведение всех внутренних маршрутов KANSO на мобильных и планшетных ширинах, не изменяя утверждённую главную страницу и десктопную компоновку от 1025 px.

## Scope

Проверяем маршруты:

- `/catalog` — каталог, toolbar, фильтры, карточки и пагинация;
- `/product/[id]` — галерея, информация о товаре, действия и связанные товары;
- `/favorites` и `/wishlist` — карточки, пустые и заполненные состояния;
- `/cart` — позиции корзины, изменение количества, удаление и итоговый блок;
- `/checkout` — форма, порядок полей и итог заказа;
- `/account` — форма входа и состояния личного кабинета;
- `/journal`, `/journal/[slug]` и `/journal/japanese-approach` — сетки, статьи и editorial-композиции;
- `/ritual` — содержимое страницы ритуала;
- общие header, меню, поиск, footer, кнопки, формы и focus-состояния на этих маршрутах.

Главная `/` исключена из реализации: её адаптивный этап завершён и используется только для регрессионной проверки общих компонентов.

## Контрольные ширины

- 320 px — минимальный мобильный экран;
- 390 px — основной мобильный экран;
- 768 px — узкий планшет;
- 1024 px — широкий планшет;
- 1440 px — контроль того, что десктоп не изменился.

Промежуточные размеры проверяются при обнаружении breakpoint-зависимых дефектов.

## Критерии качества

На ширинах до 1024 px:

- отсутствует горизонтальный скролл страницы;
- текст, изображения, формы и элементы управления не обрезаются;
- блоки не накладываются и не прилипают друг к другу;
- заголовки сохраняют целые нижние выносные элементы букв;
- кнопки и ссылки остаются видимыми, читаемыми и доступными для нажатия;
- поля форм имеют корректный порядок и удобную ширину;
- карточки переходят в подходящее число колонок без чрезмерного сжатия;
- sticky- и motion-эффекты имеют безопасное статичное поведение при `prefers-reduced-motion`;
- keyboard focus остаётся видимым.

На ширине 1440 px визуальная геометрия и поведение остаются без изменений.

## Подход

Используется evidence-first аудит по маршрутам:

1. Для каждого маршрута фиксируется RED-состояние на контрольных ширинах: переполнение, пересечения, выход элементов за viewport и визуальные дефекты.
2. Причина дефекта определяется по DOM-геометрии и действующим CSS-правилам.
3. Вносится минимальное исправление только для диапазона до 1024 px, преимущественно через локальные media queries и существующие классы.
4. Тот же маршрут повторно проверяется на всех контрольных ширинах.
5. После группы маршрутов проверяются общие компоненты и главная страница на отсутствие регрессий.

Глобальная переработка компонентов, изменение контента, бизнес-логики и demo-данных не входят в scope.

## Архитектура изменений

Основные изменения ожидаются в `src/app/globals.css`. Компоненты и страницы изменяются только тогда, когда CSS не может корректно решить проблему без ухудшения семантики или accessibility. Новые зависимости не добавляются.

Исправления группируются по функциональным зонам:

- catalog/product;
- commerce/account;
- journal/ritual;
- shared layout and controls.

## Проверка

Для каждого маршрута сохраняется таблица результатов по контрольным ширинам. Автоматизированная геометрическая проверка дополняется визуальным просмотром начала, середины и конца длинных страниц, а также открытых меню и интерактивных состояний.

Перед завершением обязательны:

- `npm run lint`;
- `npm run typecheck`;
- `npm run build`;
- `git diff --check`;
- финальная browser-матрица 320/390/768/1024 px;
- контроль главной и внутренних страниц при 1440 px.

## Ограничения

- Не менять стили и компоновку от 1025 px.
- Не менять утверждённую структуру главной страницы.
- Не устанавливать зависимости.
- Не придумывать бизнес-, юридические или коммерческие данные.
- Сохранять существующую визуальную систему KANSO.
